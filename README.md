# SmakHub 0.5

SmakHub допомагає знаходити рецепти за продуктами, зберігати страви,
планувати меню й публікувати власні рецепти після модерації.

Команда бригади №4: Калюх Р. Д. (КА-41), Худікова М. В. (КА-44), Корецька М. В. (КА-45).
Повний перелік вимог і стан 0.4 задокументовано в матриці аудиту.

## Структура

- HTML-сторінки в корені — головна, каталог, рецепт, контакти, акаунт,
  збережене, редактор рецептів, модерація, кухонний планувальник і 404.
- `css/` — базові стилі, макети, компоненти й адаптивність. `style.css`
  об’єднує файли через `@import`. Flexbox організовує рядки та навігацію,
  Grid організовує каталог і колонки основних сторінок, медіазапити
  змінюють макет для вузьких екранів.
- `js/` — пошук, Supabase Auth, рецепти, модерація, спільнота,
  планувальник та перемикання мови.
- `supabase/` — SQL у порядку виконання.
- `server/` — Cloudflare Worker для адрес /recipes/slug та HTML для пошуковиків.
- `scripts/build.cjs` — збирає публічну папку `dist/`.
- `checks/` — локальні результати перевірки.

## Оновлення чинного сайту з версії 0.4

1. У поточному проєкті Supabase, де вже виконані 001 і 002, відкрийте
   SQL Editor і запустіть 003a, 003b, 003c та 003d за порядком, або весь файл
   `smakhub-05-db.sql`. Залиште той самий проєкт Supabase та домен сайту.
2. У Table Editor → smak_members знайдіть UUID свого акаунта з
   Authentication → Users і встановіть `is_admin = true` саме для нього.
   Після входу у своєму профілі ви побачите посилання «Модерація».
3. У Supabase → Authentication → URL Configuration перевірте адресу
   https://smakhub.kaliukhromanpc.workers.dev і додайте точну адресу
   `https://smakhub.kaliukhromanpc.workers.dev/account?mode=recovery`
   разом із чинними адресами для реєстрації. Перевірте, що SMTP дозволяє
   надсилати листи на адреси користувачів за межами команди.
4. У терміналі відкрийте папку проєкту і виконайте:

   ```sh
   npm run build
   npx wrangler login
   npx wrangler deploy
   ```

   Якщо GitHub уже підключено до Worker, можна публікувати з GitHub після
   міграції. Build command — `npm run build`, Deploy command — `npx wrangler deploy`.
   Worker-скрипт і статичні файли публікуються разом.
5. Перевірте старий акаунт, збережені рецепти, відновлення пароля з листа,
   створення й модерацію рецепта з двох різних акаунтів та його публічну
   адресу. Міграція зберігає попередні UUID, профілі, рецепти, збережене
   й звернення. SQL-файли та облікові дані адміністратора не входять у dist.

## Локальний запуск

```sh
npm run build
npx wrangler dev
```

Для ручної перевірки прав потрібні звичайний акаунт і окремий
адміністратор. Для підтвердження швидкодії та навантаження потрібен
окремий контрольований стенд із мережевим доступом. Доступність 99% на
місяць потребує вимірювання протягом місяця.
